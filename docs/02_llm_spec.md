# 02. LLM 자연어 파싱 및 브리핑 스펙

## 1. 사용 모델 및 방식
- **모델:** Gemini 2.5 Flash (운영자 공용 `LLM_API_KEY` 사용)
- **출력 강제:** Structured Output(JSON Schema)을 사용해 Pydantic v2 모델(`FlightSearchQuery`)로 직접 파싱한다.
- **기준 날짜 주입:** 시스템 프롬프트에 매 요청 시점의 현재 날짜(KST, `YYYY-MM-DD`, 요일 포함)를 주입해 "다음 달 금요일", "이번 주말" 같은 상대 날짜를 정확히 계산한다.

## 2. 파싱 출력 스키마 (`FlightSearchQuery`)
| 필드명 | 타입 | 설명 및 기본값 |
| :--- | :--- | :--- |
| `origin` | `str` | 출발지 IATA 코드 (언급 없으면 기본값 `"ICN"`) |
| `destinations` | `list[str]` | 도착지 IATA 코드 목록 (최대 3개, 예: `["NRT", "HND"]`) |
| `departure_dates` | `list[str]` | 출발 날짜 후보 (`YYYY-MM-DD`, 최대 5개) |
| `stay_nights` | `int \| None` | 체류 박수 (왕복 기준, 편도면 `None`) |
| `trip_type` | `Literal["round_trip", "one_way"]` | 기본값 `"round_trip"` |
| `direct_only` | `bool` | 직항만 조회 여부 (기본값 `False`) |
| `max_budget_krw` | `int \| None` | 최대 예산(원화, 예: `300000`) |
| `passengers` | `int` | 성인 인원수 (기본값 `1`) |

## 3. IATA 공항 코드 매핑 규칙
- 한국 주요 출발지: 인천(`ICN`), 김포(`GMP`), 김해/부산(`PUS`), 제주(`CJU`)
- 복수 공항 도시 처리:
  - "도쿄" → `["NRT", "HND"]` (또는 구글 플라이트 도시 코드 지원 시 `TYO`)
  - "오사카" → `["KIX"]`
  - "런던" → `["LHR", "LGW"]`
- 모호하거나 공항을 특정할 수 없는 입력(예: "아무 데나 따뜻한 곳")은 임의로 실패시키지 않고 대표 인기 노선 2~3개로 합리적 제안하거나, 필수 정보(목적지 등)가 완전히 누락된 경우 검증 에러를 반환한다.

## 4. 2단계 검색 및 결과 브리핑 규칙
- **호출 폭발 방지:** 날짜 후보가 4일 이상이거나 "10월 중 아무 때나"처럼 범위가 넓은 경우, 1단계 최저가 날짜 탐색으로 가장 저렴한 날짜 2~3개만 먼저 추린 뒤 2단계 상세 조회를 병렬 실행한다.
- **브리핑 형식:**
  - 예산과 조건에 맞는 상위 3~5개 옵션을 선별한다.
  - 각 옵션마다 **항공사, 가격(KRW), 출도착 시간, 직항/경유 여부, 한 줄 장단점**을 한국어로 간결하게 정리한다.
