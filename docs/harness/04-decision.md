# 04. 사람의 개입 — 누가 무엇을 결정하는가

> 작성일: 2026-11-25
> 사람이 개입해야 하는 지점과 그 결정을 받는 절차의 원본은 이 문서다. [SSOT](01-ssot.md) §5는 루프와의 경계만 선언한다.
> **소유권**(누가 무엇을 바꿀 수 있나)의 원본은 SSOT §0 충돌 정책 · 보호 정책이다. 이 문서는 그 소유권을 **어떻게 주고받는가**를 정한다.
> 이 문서의 변경은 사람이 한다 (SSOT §0 보호 정책).

---

## 1. 핵심 규칙

**넘기는 법 — AI가 멈춰야 하는 지점**

- **DEC-1** 다음 중 하나에 걸리면 추측으로 메우지 않고 멈춰 **`NEEDS_HUMAN`**을 선언한다 — ① 종료 조건의 해석이 갈림 ② SSOT §0 충돌 정책에 걸림 ③ Issue 6개 항목이 비었거나 종료 조건을 참 · 거짓으로 판정할 수 없음 ④ 보호 영역(SSOT §0)을 바꿔야 한다고 판단함 ⑤ 기록과 실제 상태가 어긋남. 사람을 부르기 전에 Issue와 SSOT에서 답이 나오는지 먼저 본다 (`AGENTS.md` 탐색 규칙).
- **DEC-2** 보호 영역은 직접 고치지 않고 **변경안을 제안**한다. Issue 본문은 코멘트로, 문서 · 검증 스크립트 · 의존성(`requirements.txt`) · `.env`는 사람의 승인을 받아서 바꾼다 (SSOT §0 보호 정책 · `VER-3` · `VER-4`).
- **DEC-3** 멈추지 않고 AI가 스스로 정한 설계 판단도 시도 코멘트의 `사람 판단이 필요한 것` 칸에 전부 적는다.
- **DEC-4** **완료 판정은 사람이 한다.** 루프가 끝난 것은 완료가 아니다. 완료는 ① 자동 검증 종료 조건이 `tests/issues/test_issue_{번호}_{기능명}.py`에서 통과하고 ② `python scripts/verify.py`가 통과하고 ③ `(수동)` 종료 조건을 사람이 확인했을 때다.
- **DEC-5** **merge · 승인은 사람이 한다.** AI는 PR 생성까지만 한다. merge 없이 PR을 닫으면 사람이 중단한 것으로 본다 — AI는 스스로 재개하지 않는다.

**받는 법 — 사람의 결정이 들어오는 경로**

- **DEC-6** 사람의 승인 · 반려 · 판단은 **자연어로 AI에게 말하면 된다.** 정해진 장소도 문법도 없다. AI가 그 말을 받아 §3 「사람 판단」 코멘트로 옮겨 적는다.
- **DEC-7** **양식은 AI가 채우는 것이다.** 사람은 양식을 찾거나 외우지 않는다.
- **DEC-8** 사람이 **Issue 본문을 고치면 그 사실을 한 줄 알린다** — 형식은 자유다. AI는 본문만 보고 스스로 분류하지 않는다.

**가르는 법 — 네 갈래**

- **DEC-9** 사람의 결정은 아래 넷 중 하나로 분류해서 적는다. 이 네 이름이 루프에 건네는 유일한 신호다 (§2).

| 갈래 | 무엇인가 | 판별 |
| :--- | :--- | :--- |
| **승인** | 구현을 받아들인다 | 더 고칠 것이 없다고 말함 |
| **반려** | **요구사항대로 구현되지 않았다** — AI의 미구현 | Issue 본문은 그대로인데 결과가 그에 못 미침 |
| **판단 확정** | 갈리던 해석을 사람이 정해 줬다 | `NEEDS_HUMAN`에 대한 답. **Issue 본문은 그대로** |
| **요구사항 변경** | Issue 본문의 요구사항 · 종료 조건 · 범위가 바뀌었다 | 사람이 본문을 고쳤다고 알림 (`DEC-8`) |

> **반려와 요구사항 변경을 가르는 기준은 Issue 본문이다.** 애매하면 분류하지 않고 사람에게 되묻는다 (`DEC-1` ①).

**자문을 받는 법**

- **DEC-10** PR을 열었다면 CI `verify`가 통과한 뒤, 사람이 승인 · 반려를 판단하기 전에 **LLM 리뷰**를 돌리고 결과를 PR 코멘트로 남긴다 (§3). 리뷰는 판정이 아니라 **자문**이므로 루프를 막지 않고 합격 · 불합격을 쓰지 않는다.

## 2. 루프와의 책임 분리

| | 사람의 개입 (이 문서) | 루프 ([03-loop.md](03-loop.md)) |
| :--- | :--- | :--- |
| 무엇을 정하는가 | 누가 결정하는가 · 그 결정이 무엇인가 | 그 결정이 시도 횟수에 무엇을 하는가 |
| 수단 | `NEEDS_HUMAN` 선언 · 네 갈래 분류 · 코멘트 기록 | Issue §6 상한 · ⊕0 · ⊕1 · 초기화 |
| 모르는 것 | 몇 번째 시도인지 · 상한이 얼마인지 | 사람이 한 말이 무슨 뜻인지 |

| 이 문서의 갈래 | 루프에 주는 효과 | 근거 |
| :--- | :--- | :--- |
| 승인 | 루프 종료 · 지시 대기 | `LOOP-12` |
| 반려 | ⊕1 복귀 | `LOOP-13` |
| 판단 확정 | 시도 0으로 **초기화** | `LOOP-7` |
| 요구사항 변경 | 루프 **닫힘** | `LOOP-8` |
| `NEEDS_HUMAN` 중단 | **⊕1** — 멈추는 것은 공짜가 아니다 | `LOOP-6` |

## 3. 기록

### 사람 판단 코멘트 (Issue에 작성)

```markdown
### 사람 판단 · 승인 | 반려 | 요구사항 변경 | 판단 확정
- 받은 말: <사람이 말한 것>
- 어디서: 대화 | PR #N 리뷰 | Issue 코멘트
- 처리: 승인         → 루프 종료 · 지시 대기 (merge · 완료 선언은 사람)
        반려         → ⊕1 시도 N+1/M 로 재구현
        요구사항 변경  → 종료(LOOP-8) · 지시 대기
        판단 확정     → 초기화 시도 0/M 후 재구현 (LOOP-7)
- 다음에 할 것: 없음(대기) | <내용>
```

> 초기화는 **사람이 판단을 내렸을 때만** 일어난다. 재시도 지시("다시 해봐")만으로는 초기화되지 않는다.

### LLM 리뷰 — CI 통과 뒤의 자문 (PR에 작성)

`python scripts/verify.py`는 "코드가 규칙대로 도는가"를 보고, 사람은 "요구한 대로 됐는가"를 본다. LLM 리뷰는 그 사이를 메우는 **Issue 계약 심사**다.

| 항목 | 내용 |
| :--- | :--- |
| 언제 | CI `verify`가 통과한 뒤에만 |
| 누가 | **구현 대화 맥락이 없는 독립 서브에이전트** (프롬프트: `.agents/skills/issue-loop/references/llm-review-prompt.md`) |
| 입력 | Issue 본문 · PR diff · 시도 기록 · `docs/harness/01-ssot.md` (§0 · `REQ-*` · `ARCH-*`) |
| 보는 것 | ① 종료 조건 ↔ 구현 · 테스트 대조 (경계값 누락, 형식적 통과 테스트 포함) ② 보호 영역 침범 · Issue 범위 밖 변경 |
| 안 보는 것 | `verify.py`가 이미 검사한 것 — 타입(`mypy`) · 린트/포맷(`ruff`) · 아키텍처 `A1~A4, A7` · 테스트 통과 여부 · 스모크 |
| 출력 | PR 코멘트 (합격 · 불합격 금지, 관찰만 기록, 첫 줄 `## LLM 리뷰` 필수) |
| 힘 | 없음 (경고 · 자문). 지적이 있어도 루프를 막지 않으며 시도를 쓰지 않는다 (⊕0) |

```markdown
## LLM 리뷰 · 시도 N/M · <sha>
- 종료 조건: C1 ✓ · C2 ⚠ 캐시 4시간 경계 테스트가 시간 경과를 실제로 검증하지 않음 (tests/issues/test_issue_4_cache_ttl.py:38)
- 보호 영역: 위반 없음
- 범위 밖 변경: 없음
- 사람이 볼 것: C2
```

**보고서는 PR에, 그 보고서로 내린 결정은 Issue에** 남긴다.

## 4. 알려진 빈틈

- Issue 본문 수정을 AI가 직접 관측할 수 없다. 사람이 알리지 않으면(`DEC-8`) 옛 전제로 계속 돈다.
- 세션 밖에서 벌어진 사람의 행위(merge · close · 리뷰)는 AI가 코멘트로 옮겨 적지 않는 한 기록에 남지 않는다.
- LLM 리뷰는 같은 diff에도 다른 말을 할 수 있어 관문으로 쓰지 않는다.
- PR 없이 진행하면 LLM 리뷰가 돌지 않는다.

---

## 5. 미정

- `NEEDS_HUMAN`을 선언하기 전에 AI가 얼마나 찾아봐야 하는지의 기준 (`AGENTS.md` 탐색 규칙은 문서 범위만 정함)
- 승인 뒤 사람이 아무 말 없이 멈췄을 때의 처리
- 협업자가 여러 명일 때의 결정 권한 (현재 1인 운영자 전제)
